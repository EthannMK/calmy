# KODA end-to-end QA audit, 13 Oct 2026 (second pass)

Scope: the code at commit `2023026` plus the fixes below, run locally with the real demo data and with sign-in ON
(the deployed default). Nothing here touched the deployed site's data. Gemini, live AviationStack calls and real
phones were not exercised: those need credentials this environment does not have. Model behaviour was tested with
a simulated model response.

## A. Overall assessment

| Area | State, from what was run |
|---|---|

| Insurance logic | Payout boundaries are exact (179 min pays 0, 180 pays tier 1, 360 pays tier 2). Duplicate events never pay twice; a growing delay tops up once; a shrinking delay is not clawed back. Cover cannot be bought once a delay of 30 min is known or after departure. Four open questions are listed in section E. |

## D. Remaining risks

- Demo routes (`/api/demo/*`) and the flight webhook stay open in demo mode by design. Anyone can reset the shared demo or trigger a payout on it. Two judges at once share one database.
- `POST /api/flights/{code}/refresh` and `/api/outlet/scan` need no sign-in: the first can use up the live flight budget, the second can mark a voucher used by its code.
- State is lost on every deploy or restart, and the app must run as one instance.
- A payout on an *estimated* departure can be made before the flight leaves, and is never reduced if the estimate shrinks (D3).
- Claim timelines carry fixed illustrative step times (0s, 1s, 3s, 8s). The measured time is on the Overview.
